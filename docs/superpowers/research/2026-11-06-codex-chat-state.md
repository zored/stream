# Codex Desktop: состояния чатов для общего тайла

Дата: 2026-11-06. Продолжение [исследования интерфейсов](2026-11-06-codex-external-integration.md) и уточнение задачи 2 [плана](../plans/2026-11-06-codex-desktop.md).

## Решение до реализации

Подтверждённого полного фильтра чатов Codex для тайла пока нет. `archived=0` обозначает каталог, а не очередь внимания. Не добавлять весь каталог на тайл. Не начинать реализацию задачи 2 на основании старой отметки «AX проверено»: в этой сессии UI не исследовался. Сведения прежнего отчёта остаются историческими наблюдениями с указанными там ограничениями.

Состояние следует разделить на независимые признаки: выбранный чат, фокус приложения, выполнение хода, открытый вопрос, непрочитанность, архивирование. Последний завершённый ход не означает завершение задачи и не исключает открытый асинхронный вопрос.

## Доказательства этой сессии

Чтение SQLite выполнялось через URI `mode=ro`; читались схемы и служебные поля. Чтение JSON и логов не сопровождалось выводом переписки. UI, AX, CDP, инъекции, изменение настроек и запуск второго app-server не применялись.

Её охват отличается от 15 ID в JSON; считать её полным источником непрочитанности Desktop нельзя. У последних ходов 10 потоков найден inProgress, но только один совпал с active_chat_turns на момент сопоставления.

Источники: указанные локальные файлы на этой машине; инструмент `codex_app.list_threads` в текущем чате; раздел «Локальная разведка» предыдущего отчёта для асинхронного вопроса. Числа являются снимками, не константами.

[Официальная документация OpenAI](https://learn.chatgpt.com/docs/app-server), разделы Read a stored thread, Track thread status changes и List threads: `thread/read` не загружает поток, runtime может быть `notLoaded`; уведомления статуса относятся к загруженным потокам; `archived=false` фильтрует историю. Это не доказательство подключения внешнего демона к runtime Desktop. На прочитанной странице `firstUnread` не найден; новый read-state из main нельзя автоматически приписывать установленной сборке.

## Контракт будущего адаптера

Каждый признак хранить с provenance и состоянием known/unknown. Ключ чата включает источник и host/account identity; один UUID недостаточен для объединения источников. Ошибка чтения, неизвестная версия, чужая identity или несогласованный снимок дают unknown и диагностическое сообщение, а не read/done.

Предлагаемый фильтр после валидации: подтверждённый неархивный чат включается, когда подтверждено выполнение, открытый вопрос или непрочитанность. Известное ожидание имеет приоритет над выполнением; завершённый непрочитанный результат остаётся до подтверждения чтения. Прочитанный idle-чат не включается. Неизвестные признаки не превращаются в положительные. Дочерний чат требует подтверждённого parent edge; неизвестный parent не делает его корневым. Текущий выбранный чат задаёт кольцо только вместе с подтверждённым фокусом и согласованной идентичностью, а не добавляет весь каталог.

Это проект контракта, не подтверждённый фильтр. Пока отсутствует проверка UI, безопасный результат для новых Codex-элементов: не публиковать их как достоверную очередь. Пропажа источника должна быть видимой ошибкой; сохранённый последний снимок можно обозначать только как устаревший, без живого статуса.

Для работы требуется подтвердить текущую identity и текущий запуск. История может отставать: один из двух активных потоков ещё не совпал с последним inProgress в проекции thread_turns, поэтому обязательный join теряет живые чаты. Расхождение требует повторного согласованного снимка; отсутствие активной строки не означает completed. Для завершения требуется явный терминальный статус последнего хода; failed/interrupted не изображать успешным завершением. Асинхронное ожидание остаётся отдельным unknown даже при completed.

## Внешняя проверка человеком

Computer Use запрещает автоматизировать само ChatGPT/Codex. Не заменять его вызовами AX из shell, AppleScript, Swift, существующим бинарником Stream или другим драйвером. Здесь такая проверка не выполнялась. Человек может сам снять наблюдения через уже доступный Accessibility Inspector; разрешения TCC и глобальные настройки в рамках исследования не менять.

1. В отдельном тестовом чате вручную запустить короткий ход и открыть другой чат. Сопоставить индикатор работы с active_chat_turns и последним thread_turns по ID; сохранить только служебные поля и время.
2. После ответа записать точку непрочитанности, membership ID в выбранном account/identity bucket и terminal status. Вручную открыть чат и повторить чтение. Проверить явно помеченный unread и архивирование тестового чата отдельно.
3. Переключить два чата, затем другое приложение. Снять AXRole/AXTitle/AXIdentifier окна и выбранной строки, признак selection, frontmost bundle/PID и время. Сопоставить с последовательностью active=true/false в логах. Одинаковые заголовки не использовать как идентификатор.
4. На тестовой карточке вопроса вручную записать AXRole, AXIdentifier, selected/enabled для карточки и вариантов без текста вопроса. Снять DB/JSON до карточки, во время, после ручных Skip/Dismiss/ответа. Проверить, различимы ли закрытие и ожидание без AX. Не отправлять ответы из исследовательского инструмента.
5. По желанию человека отдельно проверить несколько вопросов, смену чата при открытой карточке, два окна и перезапуск Desktop. Наблюдать, очищаются ли активные строки, как меняется launch_id и сохраняется ли unread. Закрывать приложение только после завершения других работ.
6. Для каждого случая зафиксировать ID тестового чата, версию приложения, время, ожидаемый и фактический признак, источник и результат. До совпадения нескольких переходов не менять отметку на «подтверждено».

До этих проверок остаются блокерами: текущий фокус/чат, точная непрочитанность UI, восстановление live-состояния и закрытие асинхронного вопроса. Код продукта и глобальные настройки не изменялись.
