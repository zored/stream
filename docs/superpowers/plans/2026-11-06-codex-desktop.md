# Codex Desktop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить чаты Codex Desktop на общий тайл переключение модели и effort и ответы на вопросы физическими кнопками при его фокусе.

**Architecture:** Общая модель тайла получает источник и состояние каждой сессии; отдельный адаптер Codex обеспечивает чтение состояния и переход к чату. Существующий переключатель направляет операции в адаптер приложения в фокусе; особенности Codex сначала проверяются на живом приложении, не предполагаются заранее.

**Tech Stack:** Go, macOS Accessibility/Objective-C, SVG, Companion.

**Spec:** `docs/superpowers/specs/2026-11-06-codex-desktop-design.md`.

## Global Constraints

- Прочитать `CLAUDE.md`, `docs/invariants.md`, `docs/agents.md`, `docs/ai-switch.md` и `docs/controls.md` до изменений.
- Claude остаётся функциональным; глобальные настройки и занятый `notify` не менять без отдельного согласования.
- Поддерживаемые модели: `6.1 Terra`, `6.1 Sol`; effort: `low`, `medium`, `high`. Недоступное значение не имитировать.
- Все действия направлять в проверенный процесс и повторно проверять фокус непосредственно перед применением; не менять случайно открытый чат.
- Не печатать содержимое чатов, секреты или токены при исследовании и тестировании.
- Коммиты и push только по отдельному разрешению в чате; не трогать параллельные изменения других сессий.

## Review Focus

- Пропавший источник Codex или недоступный AX: нет ложных статусов, ошибка видна в логах; тест адаптера.
- Смена фокуса во время задержки переключателя: действие не уходит в другое приложение; тест маршрутизации и ручная проверка.
- Несовпадающие или неизвестные состояния: не выводить как завершённые; тест преобразования.
- Одинаковые ID у разных источников и повторное чтение: сессии не перетирают друг друга, нет дублей; тест объединения.
- Вопрос исчез или фокус сменился между нажатием и отпусканием: ответ не попадает в другой чат, обычное действие не срабатывает на отпускании; тест режима выбора.
- Прочитанный, архивный или дочерний чат: корректная форма и удаление без регрессии Claude; тесты объединения и SVG.

### Результаты исследования 2026-11-06

- **Проверено:** запущенное приложение называется ChatGPT, bundle ID `com.openai.codex`, версия `26.1103.31037`; CLI `codex-cli 0.153.2`.
- **Проверено по схеме и локальной базе:** `~/.codex/state_5.sqlite`, таблица `threads`, содержит `id`, `title`, `cwd`, `archived`, `updated_at_ms`, `source`, `thread_source`, `model`, `reasoning_effort`, `attached_thread_parent_id`; у части дочерних сессий parent также зашит в JSON поля `source`. Схема частная и может меняться; актуальность и полнота для интерфейса не подтверждены.
- **Проверено внутри приложения:** инструмент `list_threads` возвращает `id`, `status`, `cwd`, `updatedAt`, `isUnread`, `hostId`, `kind`; среди результатов видны активные Codex-чаты. Доступность этого инструмента внешнему демону не установлена, и её нельзя предполагать.
- **Прочитано в локально сгенерированной схеме протокола app-server:** `ThreadStatus` описывает `notLoaded`, `idle`, `systemError`, `active` и флаги `waitingOnApproval` / `waitingOnUserInput`; есть уведомление изменения статуса. Это схема, а не подтверждение, что отдельный клиент увидит сессии приложения или сможет подписаться на них.
- **Прочитано в схеме:** `ThreadSettingsUpdateParams` позволяет передать `threadId`, `model`, `effort` для последующих ходов; `TurnSettingsUpdateParams` отдельно описывает экспериментальное изменение активного хода. `ModelListResponse` описывает модели и доступные усилия. Поведение, доступность моделей и влияние на интерфейс не проверены; вызовы изменения не выполнялись.
- **Прочитано в схеме:** `ToolRequestUserInputParams` содержит `threadId`, `turnId`, `itemId`, `isBlocking`, список вопросов и вариантов. Доставка запроса внешнему клиенту и возможность безопасно ответить не проверены; не считать её доказанной.
- **Не проверено:** текущий видимый чат, точное соответствие непрочитанности и состояния интерфейсу, восстановление после рестарта, адресный переход к чату, модельные меню и AX карточки вопросов. Инструмент Computer Use дважды отказал в доступе к `com.openai.codex`; не обходить блокировку другими средствами управления интерфейсом.
- **Вывод:** задача 1 выполнена частично; задачи 2–4 не начинать до подтверждения оставшихся механизмов. Глобальные настройки и пользовательские чаты не изменялись.
- **Внешние интерфейсы, прочитано в публичных источниках:** [отчёт](../research/2026-11-06-codex-external-integration.md). Публичного способа подключиться к app-server Desktop нет: живые статусы, `requestUserInput` и смена model/effort доступны только процессу-владельцу потока; отдельный процесс получает `-32600` и видит `notLoaded`. Без внутренностей Codex доступны deep link `codex://threads/<id>` и каталог чатов через `thread/list` / `thread/read`. Остальное требует изменения условий; блокер и ручной эксперимент описаны в отчёте.
- **Проверено 2026-11-06, после разрешения AX и чтения `~/.codex`:** Desktop держит app-server по stdio, control socket нет, вшитый CLI `0.167.0-alpha.3.2`. Список, родитель, статус хода (`thread_turns` + `active_chat_turns`), непрочитанные (`electron-thread-read-state-v1`), текущий чат (лог и заголовок окна) читаются из файлов. Пикер читается по `AXTitle` и открывается фокусом + пробелом; effort — слайдер `Power`: Light/Standard/Extended/Extra High/Max/Ultra = `low`/`medium`/`high`/`xhigh`/`max`/`ultra`, применяется к чату сразу, `config.toml` не трогает, read-back через `AXApplicationStatus` и `thread_settings_applied`; модели — подменю `Select model` с отметкой ✓, `GPT-6.1 Sol` и `GPT-6.1 Terra` есть. Карточка вопроса — `AXRadioGroup` + `Skip`/`Send`; вопрос асинхронный, ход при этом `completed`. Подробности и непроверенное — в отчёте, раздел «Локальная разведка».
